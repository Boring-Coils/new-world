## 2. 一句话方案

仓库侧的锁只负责“取货之前的防抢”，物品一旦离开仓库就进入居民背包，
之后的结算、取消和离场都以背包里的实物为准，账本不再兼任背包。

## 3. 职责划分

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| `Inventory` | 数量、容量、预留体积 | 谁把东西带走了 |
| `CarryBag` | 居民身上有哪些物资 | 容量上限、空间预留、锁定 |
| `MaterialSystem` | 锁、预留、结算、回滚路由 | 物品此刻在谁身上 |
| `HumanWorkBehavior` | 何时取货、何时交货、何时退回 | 具体数量计算 |

## 4. 取货流程

1. 开始周期时按需求在库存上建立锁定，物品仍在仓库里，但其他居民取不到。
2. 居民到达取料仓库后调用 `take_locked(lock_id, carrier)`：数量从库存扣除、
   写入背包，同时把锁关闭。
3. 锁关闭表示“防抢任务结束”，回滚责任转为背包承担，不再由锁记录承担。

## 5. 结算流程

1. `settle_cycle` 先看周期是否已经完成或取消，已完成的一律拒绝，避免重复结算。
2. 周期绑定了有效居民时，核对背包是否满足需求，不满足直接失败。
3. 产出空间检查与原来一致：预留不足时临时寻找可用空间，全部预检通过才提交。
4. 提交时从背包扣除需求数量、释放产出预留、把产出写入库存。

## 6. 取消与离场

1. 取消周期时，背包中属于本周期的需求物资按锁记录的来源退回原库存。
2. 原库存已注销或放不下时，以来源建筑左上角为起点按距离转移。
3. 居民离场或死亡时，先由工作周期完成退回，再由 `_exit_tree` 兜底清空背包。
4. 兜底路由的距离起点优先使用雇主建筑的左上角，没有雇主时使用等待锚点，
   不使用居民死亡位置。

## 7. 不变式

- 同一份物资在任一时刻要么在某个库存里，要么在某个背包里，不同时出现在两处。
- 背包的实物数量永远不小于本周期尚未结算的需求数量。
- 已经关闭的锁不再参与回滚，避免同一批物资被退回两次。
- 背包不做容量限制，单次携带量由工作配置的需求数量间接约束。
