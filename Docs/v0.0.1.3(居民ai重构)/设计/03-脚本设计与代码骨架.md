# 03 脚本设计与代码骨架

## 1. 文件位置

```text
Scripts/Human/
├─ Human.gd                    居民数据、组件绑定、每刻调度
├─ HumanMotion.gd              唯一移动实现
├─ HumanVisual.gd              表现
└─ HumanAI/
   ├─ HumanAI.gd               协调器与对外接口
   ├─ HumanAIContext.gd        每刻决策快照
   ├─ HumanDecision.gd         纯评分与排序
   ├─ HumanStateBase.gd        状态脚本公共基类
   └─ States/
      ├─ IdleState.gd
      ├─ TravelingState.gd
      ├─ WaitingState.gd
      ├─ WorkingState.gd
      ├─ LeavingWorkState.gd
      └─ RelocatingState.gd
```

场景和脚本命名保持仓库现有规则：

- 路径和类名用 `PascalCase`。
- 变量、函数、信号用 `snake_case`。
- 常量用 `UPPER_SNAKE_CASE`。
- 新增脚本后同时提交 Godot 生成的 `.gd.uid`。

本文代码是实施骨架，不是已经完成的最终代码。实现时优先写类型、保持代码短小，
状态脚本不应复制 AI 或 Motion 的公共逻辑。

## 2. `Human.gd`

### 2.1 目标职责

- 持有居民数据和组件。
- 把 Motion 信号接到 Visual。
- 每刻固定调用 Buff、消耗和 AI。
- 对外提供 `relocate_out()` 和工作站显隐语义接口，不暴露 AI 内部动作。

### 2.2 骨架

```gdscript
extends Node2D
class_name Human

const MAX_WATER: float = 700.0
const MAX_FOOD: float = 700.0

@export var age: int = 20
@export var age_status: GlobalEnum.AgeStatus = GlobalEnum.AgeStatus.ADULT
@export var water: float = MAX_WATER
@export var food: float = MAX_FOOD

@onready var buff_system: BuffSystem = $BuffSystem
@onready var visual: HumanVisual = $Visual
@onready var motion: HumanMotion = $Motion
@onready var ai: HumanAI = $HumanAI

var in_building: Building = null


static func create() -> Human:
	return load("res://Scenes/Human/Human.tscn").instantiate() as Human


func _ready() -> void:
	buff_system.attach(self)
	visual.outfit = outfit
	visual.set_moving(false)

	motion.bind(self)
	motion.moving_changed.connect(visual.set_moving)
	motion.facing_changed.connect(visual.set_facing)

	ai.bind(self)
	TickManager.register_human(self)


func _exit_tree() -> void:
	TickManager.unregister_human(self)


func on_tick() -> void:
	buff_system.on_tick()
	_consume()
	ai.on_tick()


func relocate_out() -> void:
	ai.request_relocation()


func set_world_visibility(is_visible: bool) -> void:
	visual.visible = is_visible
```

`Human.on_tick()` 不再调用 `enforce_work_gate()`。工作闸门属于 AI 状态推进，
必须在工作目标处于 `Traveling`、`Waiting` 或 `Working` 时立即检查。

`set_world_visibility()` 是表现层语义接口。AI、状态脚本和 Motion 都不得直接调用
`human.hide()` / `human.show()`，更不得访问 `HumanVisual` 内部节点。

## 3. `HumanMotion.gd`

### 3.1 保持不变的职责

- 使用 `WorldGrid.get_path()`。
- 推进连续像素位置。
- 管理路径和路径索引。
- 选择可达出入口。
- 原子离站。
- 执行脱困。

### 3.2 需要补强的契约

#### 会创建移动状态的命令必须报告失败

当前 `move_to_building()` 在 `building == null` 时直接返回 `false`，不发出
`path_failed`。状态机如果只等信号，就会卡在 `Traveling`。应统一为：

```gdscript
func _fail_move(destination: Vector2i = INVALID_CELL) -> bool:
	path_failed.emit(destination)
	return false


func move_to_building(building: Building) -> bool:
	if not _can_move() or not is_instance_valid(building):
		return _fail_move()

	var route := _find_route_to_building(building)
	return _start_route(route, false)
```

`_start_route()` 的失败分支也只通过 `_fail_move()` 发一次信号。
保留的 `move_to_cell()`、`move_to_nearest_building()` 等命令也必须遵守同一契约。
`find_nearest_building()`、`get_ticks_to_building()` 只做查询，不改变路径，不发送
`path_failed`。

#### 脱困 no-op 必须发完成信号

当前居民已经站在可走格时，`relocate_to_nearest_walkable()` 返回 `true` 但不发
`relocation_finished`。AI 已进入 `Relocating`，会永久等待。应改为：

```gdscript
func relocate_to_nearest_walkable() -> bool:
	if not _can_move():
		return false

	var world := WorldGridGlobal.world
	var from_cell := world.world_to_cell(human.position)
	var target_cell := world.find_nearest_walkable(from_cell)
	if not is_instance_valid(human.in_building):
		human.set_world_visibility(true)
	if target_cell == from_cell:
		var already_safe := world.is_walkable(target_cell)
		if already_safe:
			if is_instance_valid(human.in_building):
				_commit_building_exit(from_cell)
			_clear_path()
			relocation_finished.emit()
			return true
		push_error("%s 脱困失败：当前格 %s 不可走，附近也没有安全格" % [human.name, from_cell])
		return false

	# 其余寻路、直接落地和 _start_route(route, true) 保持现有流程
	...
```

若 route 为空并直接落地，也要保证：

1. 优先通过 `_commit_building_exit()` 更新站内状态、位置和显示。
2. 清空路径。
3. 发出 `arrived`。
4. 发出 `relocation_finished`。

`relocate_to_nearest_walkable()` 是特殊的脱困命令：它不通过 `path_failed` 报告失败，
而是用返回值区分“已确认安全或已经提交脱困路线”和“没有可确认的安全结果”。如果
`find_nearest_walkable()` 仍返回不可走的原格，调用方必须记录失败，不能把居民当作
已经成功脱困。

“脚下已经是可走格”不等于“已经离开建筑”。如果 `human.in_building` 仍有效，no-op
分支也必须调用 `_commit_building_exit(from_cell)`，清理工作站占用、`in_building`
和隐藏状态后才能发 `relocation_finished`。

#### 一次移动只有一个所有者

删掉 AI 对路径索引的依赖。`path`、`path_index` 只允许 `HumanMotion` 内部写入。
外部测试使用 `get_path_size()`，AI 不访问路径。

## 4. `HumanAIContext.gd`

上下文是每次决策使用的短期快照。它不持有建筑引用，也不负责路径。

```gdscript
extends RefCounted
class_name HumanAIContext

var water_ticks_left: float = 0.0
var food_ticks_left: float = 0.0
var can_work: bool = false

var water_weight_multiplier: float = 1.0
var food_weight_multiplier: float = 1.0
var work_weight_multiplier: float = 1.0


func refresh(human: Human) -> void:
	var consume_multiplier := maxf(
		human.buff_system.get_consume_multiplier(),
		0.0,
	)
	var water_per_tick := (
		human.get_daily_water()
		/ float(TickManager.TICKS_PER_DAY)
		* consume_multiplier
		+ human.buff_system.get_water_drain_per_tick()
	)
	var food_per_tick := (
		human.get_daily_food()
		/ float(TickManager.TICKS_PER_DAY)
		* consume_multiplier
		+ human.buff_system.get_food_drain_per_tick()
	)
	water_ticks_left = _get_ticks_left(
		human.water,
		water_per_tick,
	)
	food_ticks_left = _get_ticks_left(
		human.food,
		food_per_tick,
	)

	can_work = human.buff_system.can_work()
	water_weight_multiplier = human.buff_system.get_weight_multiplier(
		HumanAI.Goal.WATER
	)
	food_weight_multiplier = human.buff_system.get_weight_multiplier(
		HumanAI.Goal.FOOD
	)
	work_weight_multiplier = human.buff_system.get_weight_multiplier(
		HumanAI.Goal.WORK
	)


func _get_ticks_left(amount: float, per_tick: float) -> float:
	if per_tick <= 0.0:
		return INF
	return maxf(amount, 0.0) / per_tick
```

为了区分“倍率”和“固定逐刻扣减”，需要同时扩展 Buff 汇总接口：

```gdscript
# BuffBase 默认返回 0.0；Thirst 返回 drain * stacks。
func get_water_drain_per_tick() -> float
func get_food_drain_per_tick() -> float

# BuffSystem 对所有有效 Buff 求和。
func get_water_drain_per_tick() -> float
func get_food_drain_per_tick() -> float
```

这是计算速率接口，不改变 `Thirst.on_tick()` 的实际扣水逻辑。`Thirst` 应让
`on_tick()` 扣减 `get_water_drain_per_tick()` 的返回值，避免“上报速率”和“实际扣减”
各写一份而漂移。Context 必须合并基础消耗、消耗倍率和直接扣减；只在决策函数里
读取上下文，不要每比较一次目标就重新遍历 Buff。

## 5. `HumanDecision.gd`

### 5.1 评分公式

沿用当前行为基线：

```text
water_score =
    (URGENT_TICKS * WORK_WEIGHT)
    / max(water_ticks_left, 1)
    * water_weight_multiplier

food_score =
    (URGENT_TICKS * WORK_WEIGHT)
    / max(food_ticks_left, 1)
    * food_weight_multiplier

work_score =
    WORK_WEIGHT
    * work_weight_multiplier
```

其中：

```gdscript
const WORK_WEIGHT: float = 10.0
const URGENT_GAME_SECONDS: float = 36.0 * 60.0
const WORK_INTERRUPT_MARGIN: float = 1.15
```

`URGENT_TICKS = URGENT_GAME_SECONDS / TickManager.GAME_SECONDS_PER_TICK`。

### 5.2 排序实现

```gdscript
extends RefCounted
class_name HumanDecision

const WORK_WEIGHT: float = 10.0
const URGENT_GAME_SECONDS: float = 36.0 * 60.0
const WORK_INTERRUPT_MARGIN: float = 1.15


static func rank_goals(context: HumanAIContext) -> Array[int]:
	var urgent_ticks := URGENT_GAME_SECONDS / TickManager.GAME_SECONDS_PER_TICK
	var scale := urgent_ticks * WORK_WEIGHT
	var candidates: Array[Dictionary] = []

	candidates.append({
		"goal": HumanAI.Goal.WATER,
		"score": scale / maxf(context.water_ticks_left, 1.0)
			* context.water_weight_multiplier,
		"priority": 0,
	})
	candidates.append({
		"goal": HumanAI.Goal.FOOD,
		"score": scale / maxf(context.food_ticks_left, 1.0)
			* context.food_weight_multiplier,
		"priority": 1,
	})

	if context.can_work:
		candidates.append({
			"goal": HumanAI.Goal.WORK,
			"score": WORK_WEIGHT * context.work_weight_multiplier,
			"priority": 2,
		})

	candidates.sort_custom(
		func(a: Dictionary, b: Dictionary) -> bool:
			var score_a: float = a["score"]
			var score_b: float = b["score"]
			if not is_equal_approx(score_a, score_b):
				return score_a > score_b
			return int(a["priority"]) < int(b["priority"])
	)

	var ranked: Array[int] = []
	for candidate in candidates:
		ranked.append(int(candidate["goal"]))
	return ranked


static func should_interrupt_work_for_goal(
	context: HumanAIContext,
	goal: int,
) -> bool:
	var urgent_ticks := URGENT_GAME_SECONDS / TickManager.GAME_SECONDS_PER_TICK
	var scale := urgent_ticks * WORK_WEIGHT
	var candidate_score := 0.0
	if goal == HumanAI.Goal.WATER:
		candidate_score = (
			scale
			/ maxf(context.water_ticks_left, 1.0)
			* context.water_weight_multiplier
		)
	elif goal == HumanAI.Goal.FOOD:
		candidate_score = (
			scale
			/ maxf(context.food_ticks_left, 1.0)
			* context.food_weight_multiplier
		)
	else:
		return false

	var current_work_score := WORK_WEIGHT * context.work_weight_multiplier
	return candidate_score >= current_work_score * WORK_INTERRUPT_MARGIN
```

### 5.3 平手规则

平手优先级为：

1. 水。
2. 食物。
3. 工作。

该规则由 `priority` 字段显式实现。不要再依赖“先写哪个 `if` 就先选哪个”。

### 5.4 禁止副作用

`HumanDecision` 不调用：

- `find_nearest_building()`
- `send_event()`
- `move_to_building()`
- 任何写 `goal`、`target` 或位置的方法

建筑可达性由 AI 在拿到排序后逐项尝试。

## 6. `HumanAI.gd`

### 6.1 常量与状态

```gdscript
extends Node
class_name HumanAI

signal state_changed(old_state: StringName, new_state: StringName)
signal goal_changed(old_goal: int, new_goal: int)

enum Goal {
	NONE,
	WATER,
	FOOD,
	WORK,
}

const DECISION_INTERVAL: int = 5

const EVENT_GOAL_SELECTED: StringName = &"goal_selected"
const EVENT_ARRIVED: StringName = &"arrived"
const EVENT_PATH_FAILED: StringName = &"path_failed"
const EVENT_TARGET_INVALID: StringName = &"target_invalid"
const EVENT_SERVICE_COMPLETED: StringName = &"service_completed"
const EVENT_WORK_STARTED: StringName = &"work_started"
const EVENT_WORK_INTERRUPTED: StringName = &"work_interrupted"
const EVENT_WORK_CANCELLED: StringName = &"work_cancelled"
const EVENT_EXIT_ROUTE_STARTED: StringName = &"exit_route_started"
const EVENT_RELOCATION_REQUESTED: StringName = &"relocation_requested"
const EVENT_RELOCATION_FINISHED: StringName = &"relocation_finished"
const EVENT_RELOCATION_FAILED: StringName = &"relocation_failed"

@onready var state_chart: StateChart = $StateChart

var human: Human
var motion: HumanMotion

var _context := HumanAIContext.new()
var _goal: int = Goal.NONE
var _target: Building = null
var _active_state: HumanStateBase = null
var _active_state_key: StringName = &""

var _tick_count: int = 0
var _decision_offset: int = 0
var _force_decision: bool = true
var _pending_relocation: bool = false
```

### 6.2 绑定

```gdscript
func bind(host: Human) -> void:
	if human == host:
		return

	human = host
	motion = human.motion
	_decision_offset = randi() % DECISION_INTERVAL

	_bind_state_nodes(state_chart)
	_connect_motion_signals()


func _bind_state_nodes(node: Node) -> void:
	for child in node.get_children():
		if child is HumanStateBase:
			child.bind(self, human)
		_bind_state_nodes(child)


func _connect_motion_signals() -> void:
	if not motion.arrived.is_connected(_on_motion_arrived):
		motion.arrived.connect(_on_motion_arrived)
	if not motion.path_failed.is_connected(_on_motion_path_failed):
		motion.path_failed.connect(_on_motion_path_failed)
	if not motion.relocation_finished.is_connected(_on_relocation_finished):
		motion.relocation_finished.connect(_on_relocation_finished)
```

不需要在 AI 中连接 `moving_changed` 和 `facing_changed`，它们已由 `Human`
接到 Visual。

### 6.3 每刻入口

```gdscript
func on_tick() -> void:
	if not is_instance_valid(human):
		return

	_tick_count += 1
	_context.refresh(human)

	if not state_chart.is_node_ready() or _active_state_key == &"":
		return

	if _pending_relocation:
		_pending_relocation = false
		state_chart.send_event(EVENT_RELOCATION_REQUESTED)

	state_chart.step()

	if motion.is_moving() or motion.is_relocating():
		motion.on_tick()
```

不要把 `_pending_relocation` 放进 `_ready()` 立即发送。若它由 deferred 初始化前的
极早调用产生，在第一次 tick 补发最稳定。`state_chart.is_node_ready()` 只能说明节点
完成 `_ready()`，不能说明 deferred 的初始状态已经激活；因此必须同时检查
`_active_state_key != &""`，否则初始化窗口内发出的 `relocation_requested` 会被空闲
状态图丢弃。

待补发的脱困请求在 `step()` 前发送，使 `Relocating` 优先于同一个 tick 的普通空闲决策。

### 6.4 移动信号

```gdscript
func _on_motion_arrived(_destination: Vector2i) -> void:
	state_chart.send_event(EVENT_ARRIVED)


func _on_motion_path_failed(_destination: Vector2i) -> void:
	state_chart.send_event(EVENT_PATH_FAILED)


func _on_relocation_finished() -> void:
	state_chart.send_event(EVENT_RELOCATION_FINISHED)
```

`arrived` 在脱困结束前也可能发出。当前 `Relocating` 没有 `arrived` 转换，
因此不会误切状态；真正结束脱困只依赖 `relocation_finished`。

### 6.5 空闲决策

```gdscript
func on_idle_entered() -> void:
	_force_decision = true
	clear_goal()
	motion.stop()


func try_select_idle_goal() -> bool:
	if not _consume_decision_slot():
		return false

	for goal in HumanDecision.rank_goals(_context):
		if goal == Goal.WORK and not _context.can_work:
			continue

		var building := _find_target_for_goal(goal)
		if building == null:
			continue

		_set_goal(goal, building)
		return true

	return false


func _consume_decision_slot() -> bool:
	if _force_decision:
		_force_decision = false
		return true

	if (_tick_count + _decision_offset) % DECISION_INTERVAL != 0:
		return false
	return true


func _find_target_for_goal(goal: int) -> Building:
	match goal:
		Goal.WATER:
			return motion.find_nearest_building(GlobalEnum.BuildingType.WATER)
		Goal.FOOD:
			return motion.find_nearest_building(GlobalEnum.BuildingType.FOOD)
		Goal.WORK:
			var building := motion.find_nearest_building(GlobalEnum.BuildingType.WORK)
			return building if building is WorkStation else null
		_:
			return null
```

使用显式 `match`，不要依赖 `Goal` 编号恰好等于 `BuildingType` 的编号。

### 6.6 目标读写

```gdscript
func _set_goal(new_goal: int, new_target: Building) -> void:
	var old_goal := _goal
	_goal = new_goal
	_target = new_target
	if old_goal != new_goal:
		goal_changed.emit(old_goal, new_goal)


func clear_goal() -> void:
	_set_goal(Goal.NONE, null)


func get_goal() -> int:
	return _goal


func get_target() -> Building:
	return _target


func is_target_valid() -> bool:
	if not is_instance_valid(_target):
		return false
	if not _target.is_placed or not TickManager.buildings.has(_target):
		return false

	match _goal:
		Goal.WATER:
			return _target.building_type == GlobalEnum.BuildingType.WATER
		Goal.FOOD:
			return _target.building_type == GlobalEnum.BuildingType.FOOD
		Goal.WORK:
			return _target is WorkStation
		_:
			return false


func is_work_allowed() -> bool:
	return _context.can_work
```

对外只提供 `get_goal()`、`get_target()` 和调试快照，不提供公开可写字段。

### 6.7 旅程与服务动作

```gdscript
func start_travel_to_current_target() -> bool:
	if not is_target_valid():
		state_chart.send_event(EVENT_TARGET_INVALID)
		return false

	if motion.is_moving():
		# 从 LeavingWork 进入 Traveling 时，路径已经在离站时建立。
		return true

	return motion.move_to_building(_target)


func complete_current_wait() -> StringName:
	if not is_target_valid():
		return EVENT_TARGET_INVALID

	match _target.building_type:
		GlobalEnum.BuildingType.WATER:
			human.water = Human.MAX_WATER
			clear_goal()
			return EVENT_SERVICE_COMPLETED
		GlobalEnum.BuildingType.FOOD:
			human.food = Human.MAX_FOOD
			clear_goal()
			return EVENT_SERVICE_COMPLETED
		GlobalEnum.BuildingType.WORK:
			return EVENT_WORK_STARTED
		_:
			clear_goal()
			return EVENT_TARGET_INVALID
```

工作等待完成后不提前 `enter()`。真正进入工作站由 `WorkingState._on_enter()`
负责，确保站内状态和 `Human.in_building` 同时成立。

### 6.8 工作进入、检查和离开

```gdscript
func enter_current_workstation() -> bool:
	if not is_target_valid() or not (_target is WorkStation):
		return false

	var station := _target as WorkStation
	station.enter(human)
	human.in_building = station
	human.set_world_visibility(false)
	return true


func try_interrupt_work_goal() -> bool:
	if not _consume_decision_slot():
		return false

	for next_goal in HumanDecision.rank_goals(_context):
		if not HumanDecision.should_interrupt_work_for_goal(_context, next_goal):
			continue

		var next_target := _find_target_for_goal(next_goal)
		if next_target == null:
			continue

		_set_goal(next_goal, next_target)
		return true

	return false


func evaluate_work_interrupt() -> int:
	if not is_target_valid():
		return WorkInterrupt.CANCEL
	if human.in_building != _target:
		return WorkInterrupt.CANCEL
	if not is_work_allowed():
		return WorkInterrupt.CANCEL

	if try_interrupt_work_goal():
		return WorkInterrupt.TRAVEL

	return WorkInterrupt.NONE


func leave_work_now() -> bool:
	if is_instance_valid(human.in_building):
		return motion.leave_current_building()
	human.in_building = null
	human.set_world_visibility(true)
	return false
```

`WorkInterrupt` 可以定义为 AI 内部枚举：

```gdscript
enum WorkInterrupt {
	NONE,
	CANCEL,
	TRAVEL,
}
```

注意：`can_work() == false` 的硬闸门在每次 `Traveling`、`Waiting`、`Working`
step 时检查，不受 `DECISION_INTERVAL` 限制。只有生存评分的重新计算受决策周期限制。

### 6.9 脱困

```gdscript
func request_relocation() -> void:
	if not state_chart.is_node_ready() or _active_state_key == &"":
		_pending_relocation = true
		return
	state_chart.send_event(EVENT_RELOCATION_REQUESTED)


func begin_relocation() -> bool:
	clear_goal()
	return motion.relocate_to_nearest_walkable()


func report_relocation_failure() -> void:
	push_error("%s 脱困命令失败，检查 HumanMotion 的格坐标日志" % human.name)
```

`RelocatingState` 在 `begin_relocation()` 返回 `false` 时执行一次安全离站，
记录失败，然后发送 `relocation_failed`，防止居民卡在脱困状态。失败日志必须明确
说明失败发生在哪个格子；这个日志由能访问网格的 `HumanMotion` 输出，AI 只补充
居民上下文，不能把失败当成成功脱困。

## 7. `HumanStateBase.gd`

```gdscript
extends AtomicState
class_name HumanStateBase

var _controller: HumanAI
var _human: Human
var _bound: bool = false


func _ready() -> void:
	super._ready()
	state_entered.connect(_handle_state_entered)
	state_stepped.connect(_handle_state_stepped)
	state_exited.connect(_handle_state_exited)


func bind(controller: HumanAI, host: Human) -> void:
	_controller = controller
	_human = host
	_bound = true


func _handle_state_entered() -> void:
	if not _bound:
		push_error("%s 在绑定前被激活" % name)
		return
	_controller.notify_state_entered(_state_key(), self)
	_on_enter()


func _handle_state_stepped() -> void:
	if _bound:
		_on_step()


func _handle_state_exited() -> void:
	if _bound:
		_on_exit()


func _send(event: StringName) -> void:
	_controller.send_event(event)


func get_debug_data() -> Dictionary:
	return {}


func _state_key() -> StringName:
	return StringName(name.to_snake_case())


func _on_enter() -> void:
	pass


func _on_step() -> void:
	pass


func _on_exit() -> void:
	pass
```

信号连接发生在所有状态节点的 `_ready()`。`StateChart` 会 deferred 进入初始状态，
而 `Human._ready()` 在 deferred 前完成绑定，因此首次 `Idle` 进入时状态脚本已经拿到
`HumanAI` 和 `Human`。

`HumanStateBase` 覆盖了插件基类 `StateChartState` 的 `_ready()`，所以必须显式调用
`super._ready()`。漏掉这一步会让插件没有缓存当前状态所属的 `_chart`，直到第一次
转换时才以空引用报错。

## 8. 状态脚本

### 8.1 `IdleState.gd`

```gdscript
extends HumanStateBase


func _state_key() -> StringName:
	return &"idle"


func _on_enter() -> void:
	_controller.on_idle_entered()


func _on_step() -> void:
	if _controller.try_select_idle_goal():
		_send(HumanAI.EVENT_GOAL_SELECTED)
```

### 8.2 `TravelingState.gd`

```gdscript
extends HumanStateBase


func _state_key() -> StringName:
	return &"traveling"


func _on_enter() -> void:
	if _controller.get_goal() == HumanAI.Goal.WORK and not _controller.is_work_allowed():
		_send(HumanAI.EVENT_WORK_CANCELLED)
		return
	_controller.start_travel_to_current_target()


func _on_step() -> void:
	if not _controller.is_target_valid():
		_send(HumanAI.EVENT_TARGET_INVALID)
		return

	if _controller.get_goal() == HumanAI.Goal.WORK:
		if not _controller.is_work_allowed():
			_send(HumanAI.EVENT_WORK_CANCELLED)
			return
		if _controller.try_interrupt_work_goal():
			_send(HumanAI.EVENT_WORK_INTERRUPTED)


func _on_exit() -> void:
	_controller.motion.stop()
```

从 `LeavingWork` 进入时，Motion 已经在移动，`start_travel_to_current_target()`
只确认路径存在，不重复寻路。

### 8.3 `WaitingState.gd`

```gdscript
extends HumanStateBase

var _wait_left: int = 0


func _state_key() -> StringName:
	return &"waiting"


func _on_enter() -> void:
	var target := _controller.get_target()
	if not is_instance_valid(target):
		_send(HumanAI.EVENT_TARGET_INVALID)
		return
	if _controller.get_goal() == HumanAI.Goal.WORK and not _controller.is_work_allowed():
		_send(HumanAI.EVENT_WORK_CANCELLED)
		return

	_wait_left = target.get_wait_ticks()
	if _wait_left <= 0:
		_finish_wait()


func _on_step() -> void:
	if not _controller.is_target_valid():
		_send(HumanAI.EVENT_TARGET_INVALID)
		return

	if _controller.get_goal() == HumanAI.Goal.WORK:
		if not _controller.is_work_allowed():
			_send(HumanAI.EVENT_WORK_CANCELLED)
			return
		if _controller.try_interrupt_work_goal():
			_send(HumanAI.EVENT_WORK_INTERRUPTED)
			return

	_wait_left -= 1
	if _wait_left <= 0:
		_finish_wait()


func _finish_wait() -> void:
	_send(_controller.complete_current_wait())


func get_debug_data() -> Dictionary:
	return {"wait_left": maxi(_wait_left, 0)}
```

### 8.4 `WorkingState.gd`

```gdscript
extends HumanStateBase


func _state_key() -> StringName:
	return &"working"


func _on_enter() -> void:
	if not _controller.is_work_allowed():
		_send(HumanAI.EVENT_WORK_CANCELLED)
		return
	if not _controller.enter_current_workstation():
		_send(HumanAI.EVENT_WORK_CANCELLED)


func _on_step() -> void:
	match _controller.evaluate_work_interrupt():
		HumanAI.WorkInterrupt.NONE:
			return
		HumanAI.WorkInterrupt.CANCEL:
			_controller.leave_work_now()
			_send(HumanAI.EVENT_WORK_CANCELLED)
		HumanAI.WorkInterrupt.TRAVEL:
			_send(HumanAI.EVENT_WORK_INTERRUPTED)
```

`WorkingState._on_exit()` 不自动离站。三种退出路径各自保证：

- `work_cancelled`：发送事件前已安全离站。
- `work_interrupted`：下一状态 `LeavingWork` 原子离站。
- `relocation_requested`：由 `Relocating` 统一处理站内离开。

### 8.5 `LeavingWorkState.gd`

```gdscript
extends HumanStateBase


func _state_key() -> StringName:
	return &"leaving_work"


func _on_enter() -> void:
	if _controller.start_travel_to_current_target():
		_send(HumanAI.EVENT_EXIT_ROUTE_STARTED)


func _on_step() -> void:
	if not _controller.is_target_valid():
		_send(HumanAI.EVENT_TARGET_INVALID)


func _on_exit() -> void:
	if is_instance_valid(_human.in_building):
		_controller.motion.leave_current_building()
```

失败事件由 Motion 契约统一发出：

- 目标已失效时，`HumanAI.start_travel_to_current_target()` 发送 `target_invalid`。
- 路线不存在或移动前置条件失败时，`HumanMotion` 发送 `path_failed`。

状态脚本不在 `else` 中重复发送失败事件，否则一次失败可能排队两个同名事件。

### 8.6 `RelocatingState.gd`

```gdscript
extends HumanStateBase


func _state_key() -> StringName:
	return &"relocating"


func _on_enter() -> void:
	if not _controller.begin_relocation():
		_controller.leave_work_now()
		_controller.report_relocation_failure()
		_send(HumanAI.EVENT_RELOCATION_FAILED)


func _on_step() -> void:
	if not _controller.is_relocating():
		_controller.report_relocation_failure()
		_send(HumanAI.EVENT_RELOCATION_FAILED)
```

`_on_step()` 是防御性兜底。正常情况下，`HumanMotion.relocation_finished`
会在移动结束的同一 tick 内转换回 `Normal`，不需要等到下一 tick；只有移动状态
意外消失时才发送 `relocation_failed`。

## 9. 场景连接与脚本资源

推荐所有信号在脚本中连接，而不是在 `Human.tscn` 里堆大量 `[connection]`：

- `Human` 连接 Motion 到 Visual。
- `HumanAI` 连接 Motion 的到达、失败和脱困信号。
- 状态脚本连接自己的 `state_entered`、`state_stepped`、`state_exited`。

这样场景只保存节点、脚本和转换配置，行为连接集中且可测试。

## 10. 公共 API 与可见性约定

### 10.1 AI 内部字段

以下字段使用下划线前缀，外部不应读取：

- `_goal`
- `_target`
- `_active_state`
- `_active_state_key`
- `_tick_count`
- `_decision_offset`
- `_force_decision`
- `_pending_relocation`
- `_context`

### 10.2 状态脚本可直接使用的 AI 接口

- `on_idle_entered()`
- `try_select_idle_goal() -> bool`
- `start_travel_to_current_target() -> bool`
- `complete_current_wait() -> StringName`
- `enter_current_workstation() -> bool`
- `is_work_allowed() -> bool`
- `try_interrupt_work_goal() -> bool`
- `evaluate_work_interrupt() -> int`
- `leave_work_now() -> bool`
- `begin_relocation() -> bool`
- `report_relocation_failure()`
- `is_relocating() -> bool`
- `is_target_valid() -> bool`
- `send_event(event)`

### 10.3 状态脚本不直接使用的接口

- `WorldGridGlobal.world`
- `Human.position`
- `HumanMotion.path`
- `HumanMotion.path_index`
- `HumanVisual.set_facing()`
- `Human.hide()` / `Human.show()`
- `WorkStation.occupants`

若某种行为确实需要新的底层操作，应先在 AI 或 Motion 增加语义明确的接口，
不要从状态节点直接穿越组件边界。
