# 建筑坐标与新增建筑

> 对应代码：`Scripts/Building/Building.gd`、`Scripts/Grid/WorldGrid.gd`
> 本文所有数字都按 1 格 = 10 像素、`CELL_SIZE = 10` 计算。

## 一句话结论

建筑只有**一个真相**：`origin_cell`，也就是**左上角那一格**。
像素位置、鼠标点、出入口坐标，全都是从它算出来的。

---

## 一、三套坐标，别混着用

| 叫法 | 类型 | 含义 | 谁提供 |
|---|---|---|---|
| 格子坐标 | `Vector2i` | 世界第几列第几行，`(0,0)` 是世界左上角第一格 | 逻辑层统一用这个 |
| 格子中心像素 | `Vector2` | 格子正中间的像素点 | `WorldGrid.cell_to_world(cell)` |
| 节点位置 | `Vector2` | 建筑节点原点的像素位置 | `Building.position` |

换算关系（`WorldGrid.gd:180`）：

```
cell_to_world(cell) = cell * 10 + (5, 5)      # 格子中心
building.position   = cell_to_world(origin) - (5, 5)   # = origin 那一格的左上角
```

**所以：建筑的节点原点 = 左上角那一格的左上角**，不是中心，不是右下。
绘制代码里 `Rect2(Vector2.ZERO, size_px)` 从原点往右下画，正好铺满自己占的格。

---

## 二、形状怎么定义

```gdscript
size_cells = Vector2i(4, 3)   # (横向格数, 纵向格数) = 宽 4 格、高 3 格
```

- `x` 是**宽**（往右几格），`y` 是**高**（往下几格）。写反了建筑就横竖颠倒。
- 占格范围：`x ∈ [origin.x, origin.x + 3]`，`y ∈ [origin.y, origin.y + 2]`，共 12 格。
- 放好以后，这 12 格全部设成**不可走**（`Building.place_at` 最后一步）。

**目前只支持矩形。** 想要 L 形、十字形、多段城墙，现在没有表达方式，需要另外加一个「占格偏移数组」。这是以后的事了，现在别硬凑。

---

## 三、出入口相对的是谁

> **相对 `origin_cell`（左上角那一格），不是建筑中心，也不是鼠标点。**

绝对格子坐标：

```
出入口绝对格 = origin_cell + entrance_offsets[i]
```

三条硬规则（`Building.can_place_at` 里逐条校验）：

1. 必须在建筑矩形**外面**
2. 必须和矩形**边相邻**——碰角不算，只认上下左右
3. 这一格本身必须**可走**（没压别的建筑或障碍）

多个出入口就写多个偏移，居民会挑最近的那个。

## 四、一张图看懂（宽 4 × 高 3）

```
            x=100   x=101   x=102   x=103
        ┌────────┬────────┬────────┬────────┐
 y=80   │        │        │        │        │   ← origin_cell = (100, 80)
        │        │        │        │        │      这 12 格是建筑本体（不可走）
 y=81   │        │        │        │        │
        │        │        │        │        │
 y=82   └────────┴────────┴────────┴────────┘
 y=83            [出]                              ← offset (1, 3)
```

- `(0, -1)` → 正上方偏左那格
- `(1, -1)` → 正上方第二格
- `(2, -1)` → 正上方第三格
- `(1, 3)`  → **正下方**第二格（因为 3 = 高 3 格，落到 y+3）

**注意：宽 4 格没有「正中间」这一格**，中心线在 x = 101.5 上。
宽 4 想在上方随便挑一格都得接受偏半格，`(1,-1)` 或 `(2,-1)` 都行，别纠结。

## 五、完整算例（可以直接抄）

```gdscript
var station := WaterStation.new()
station.size_cells = Vector2i(4, 3)
station.entrance_offsets = [Vector2i(2, -1)]
station.place_at(WorldGridGlobal.world, Vector2i(100, 80))
```

算出来是：

| 项目 | 值 |
|---|---|
| `origin_cell` | `(100, 80)` |
| 占格范围 | x 100~103，y 80~82 |
| 节点 `position` | `(1000, 800)` |
| 出入口绝对格 | `(102, 79)` |
| 鼠标点 `(102, 81)` 对应 | `origin = (102-4/2, 81-3/2) = (100, 80)` |

鼠标点→左上角的换算在 `PlacementController._origin_for()`：

```gdscript
origin = mouse_cell - Vector2i(size.x / 2, size.y / 2)   # 整数除，向下取整
```

也就是说**鼠标点的是建筑大致中心**，尺寸是奇数时会偏一格。这是有意的，不是 bug。

## 六、现在要加一种新建筑，得改 5 个地方

以加一个「诊所」为例：

1. `Scripts/Enum/GlobalEnum.gd` → `BuildingType` 加 `CLINIC`
2. 新建 `Scripts/Building/Clinic.gd` → `extends Building` + `class_name Clinic`
3. `Scripts/Debug/PlacementController.gd:13` → `Kind` 加 `CLINIC`
4. `Scripts/Debug/PlacementController.gd:204` → `_create_building` 加分支
5. `Scripts/Debug/DebugUI.gd:70` → 加按钮；`DebugUI.gd:102` → 加模式文字

漏掉第 4 或第 5 处，表现就是「按钮点了没反应」或者「名字是空的」。第 5 处还要顺带看面板宽度够不够（六个汉字约 98 像素，两列 + 间距 + 内边距 → 面板最小宽 224）。

### 子类模板

```gdscript
extends Building
class_name Clinic

## 诊所：占地 3×2，正上方开口。

func _init() -> void:
	building_type = GlobalEnum.BuildingType.CLINIC
	size_cells = Vector2i(3, 2)
	entrance_offsets = [Vector2i(1, -1)]
	body_color = Color(0.85, 0.35, 0.40)
	display_name = "诊所"
```

只要不出新玩法，行为直接继承 `Building`，`on_tick()` 和 `get_wait_ticks()` 都不用写。

## 七、注释方向错误（已修复）

`WaterStation.gd` 原来写「正上方中间那一格」，实际 `(1, 3)` 落在**正下方偏左**：
`size_cells = (4, 3)` 时 `y + 3` 在底边下面，`x = 1` 也不是正中间（宽 4 没有正中格）。

`FoodStation.gd` 的「正上方和正下方各一个」方向同样标反了：`(1, 3)` 是下方，`(2, -1)` 才是上方。

两处已按文档注释规范改正，并补全了类级文档：

- 文档注释用 `##`，`#` 只写给读代码的人看，不进文档
- 第一行是一句话摘要
- **换行一律用 `[br]`，不能靠空 `##` 行或别的方式**（代码块除外）
- 引用本文件的成员用 BBCode：`[constant WAIT_TICKS]`、`[method get_wait_ticks]`、`[member entrance_offsets]`
- 多行代码示例用 `[codeblock] ... [/codeblock]`

## 八、要不要改造（两档）

### A 档：只加辅助函数，不动结构（约半小时）

在 `Building` 里补三个小方法，以后不用到处手拼：

```gdscript
func get_rect() -> Rect2i:
	return Rect2i(origin_cell, size_cells)

func get_center_cell() -> Vector2i:
	return origin_cell + size_cells / 2

func is_cell_inside(cell: Vector2i) -> bool:
	return get_rect().has_point(cell)
```

再把「鼠标格 → origin」这件换算收进 `Building`（现在散在 `PlacementController._origin_for`），
`_hover_cell` 那套就只在一个文件里出现。**收益：加建筑时少算错坐标。**

### B 档：建筑定义表（半天，动 4 个文件）

新建一个 `BuildingDef`（`Resource`，或者一个静态字典），把「类型 / 名字 / 尺寸 / 出入口 / 颜色 / 按钮文字」集中成一张表。
然后：

- 工厂 `_create_building` 改成查表
- `DebugUI` 按表自动生成按钮，不再手写 `_add_button` 和 `_on_button` 的 match
- `GlobalEnum.BuildingType` 可以退化成字符串 id

**收益：新增建筑从「改 5 处」变成「写 1 个子类 + 加 1 条表项」。**
**风险：要动放置链路和 UI 两个文件，项目没有自动化测试，改完必须跑 `--autoplace` 并对截图。**

我的建议：**先做 A 档**，B 档等建筑超过 6~7 种、你确实觉得烦了再做。现在 3 种建筑做注册表是提前优化。
