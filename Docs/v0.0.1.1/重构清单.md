## 一、Human.gd（455 行）拆四块

### 拆完的样子

```
Scripts/Human/Human.gd          实体：状态字段 + on_tick 编排（约 120 行）
Scripts/Human/HumanNeeds.gd     数值：水/食物的消耗、上限、日耗、速度、剩余刻数
Scripts/Human/HumanBrain.gd     决策：权重比较、选目标
Scripts/Human/HumanMover.gd     移动：路径、逐刻前进、到达、等待
Scripts/Human/HumanView.gd      绘制：白模小人、衣服颜色
```

### 对应现在的行号

| 现在 | 去哪 |
|---|---|
| 34~48 常量（上限、决策间隔、权重） | `HumanNeeds` / `HumanBrain` 各拿自己的 |
| 127~141 `_consume()` | `HumanNeeds.consume(human, ticks_per_day)` |
| 143~184 日耗 / 速度 / 剩余刻数 | `HumanNeeds` |
| 191~292 决策 + 开始目标 + 找最近建筑 | `HumanBrain.decide(...)` / `HumanBrain.start_goal(...)` |
| 295~332 `evict_out()` | 留在 `Human`（这是「被挤走」的对外接口）或放 `HumanMover` |
| 338~412 移动 / 到达 / 等待 / 补给 | `HumanMover` |
| 419~455 `_draw` + 颜色 | `HumanView` |

### 关键约束

- **别把 `Human` 拆成一个只装数据的空壳**。`Human.on_tick()` 保留编排权，顺序还是「消耗 → 决策 → 行动」，读起来一眼能看明白一刻发生什么。
- `HumanNeeds`、`HumanBrain` 建议做 `RefCounted` 而不是 `Node`，别给每个居民多挂三个节点。
- `HumanView` 可以做成子节点（`Node2D` + `_draw`），`Human` 把 `visible` 转发给它；不然 `Human.gd` 里 `hide()`/`show()` 那几处会散。
- 拆分过程中**每拆一步就 headless 跑一次**，别四块一起改完再跑。

### 验收

```bash
/d/GodotEngine/Godot/godot.exe --headless --path H:/Projects/new-world --quit
/d/GodotEngine/Godot/godot.exe --headless --path H:/Projects/new-world -- --speed=600 --max-ticks=5400
```

要求：无 SCRIPT ERROR；结束时 `虚弱 0`；三种状态（WATER/WAITING、FOOD/WAITING、WORK/INSIDE_WORK）都出现过。

## 二、TestScene.gd（306 行）拆三块

### 拆完的样子

```
Scripts/TestScene.gd            只做装配：相机、网格、建筑、居民、UI、放置器（约 90 行）
Scripts/Debug/SessionStats.gd   统计：遍历居民，算出六项人数 + 一行明细
Scripts/Debug/DebugRunner.gd    调试外壳：命令行参数、定时打印、截图、退出
```

### 对应现在的行号

| 现在 | 去哪 |
|---|---|
| 40~52 `_ready` 装配 | 留在 `TestScene` |
| 54~139 相机 / 网格 / 建筑 / 居民 / 出生格 | 留在 `TestScene`（这是场景该干的事） |
| 140~161 `_setup_ui` 里的命令行解析 | `DebugRunner` |
| 164~199 `_auto_test_placement` | `DebugRunner` |
| 212~279 `_process` 统计 + 明细 + 退出 | 统计部分 → `SessionStats`，打印/退出 → `DebugRunner` |
| 282~286 `_take_screenshot` | `DebugRunner` |
| 290~306 空格暂停、1~4 倍速 | `DebugRunner`（也可以直接放 `TickManager`） |

### 关键约束

- `SessionStats` 出去的是**数据结构**（`{取水: 3, 取食: 2, ...}`），不是拼好的字符串。
  字符串拼接留在 `DebugUI` 或者 `DebugRunner` 里，这样以后换 UI 不用改统计。
- 现在 `_process` 每帧遍历所有居民算一次统计。拆的时候顺手加个「每刻算一次」的缓存，别每帧扫全城——人一多这里就是瓶颈。
- `_auto_test_placement` 依赖 `_placer`，`DebugRunner` 要通过构造参数或 `setup(placer, ui)` 拿到，不要反过来去 `get_node("../Placement")` 硬找。

### 验收

```bash

/d/GodotEngine/Godot/godot.exe --headless --path H:/Projects/new-world -- --autoplace --max-ticks=30
# 期望：水站=true 居民=true 重叠=false 压建筑=false；压着居民放建筑=true 居民被挤出来=true

# 统计与退出
/d/GodotEngine/Godot/godot.exe --headless --path H:/Projects/new-world -- --speed=600 --max-ticks=5400

# 截图（要开窗）
/d/GodotEngine/Godot/godot.exe --path H:/Projects/new-world -- --ghost=477,502 --max-ticks=40 --shot=D:/HermesProjects/temp/ghost.png
```

## 三、其他三处（可以放到下一轮）

### 1. TickManager 兼职太多

现在它同时是：时钟 + 建筑登记表 + 居民登记表 + 建筑查询服务。
`Human` 要找一个水站，得去问时钟（`TickManager.get_buildings_of_type`），语义是歪的。

建议：建筑/居民名单挪到 `WorldGridGlobal`（改名 `World` 更贴切），`TickManager` 只管 tick 和信号。
**这是跨 6 个文件的改动，收益是概念清楚，不是功能，放到最后做。**

### 2. Building.gd 混了占格和绘制

258 行里，`_draw`（186~239）和 `_draw_type_symbol` 占了一大半。
建议把绘制搬到 `BuildingView`，或者退一步：把「类型符号」改成子类各自实现 `_draw_symbol()`，基类不再用 `match building_type`。
否则每加一种建筑都要回基类加分支，违反开闭。

### 3. 全局单例约 35 处

`TickManager.` 和 `WorldGridGlobal.world.` 直接写死。
Godot 常规写法，**不建议现在改**，但心里要有数：将来做多地图、单元测试、存档切换时，这 35 处会一起咬你。
真要治，用一个 `WorldContext` 传进去，而不是每个类都伸手抓全局。

## 四、推荐执行顺序

1. `SessionStats` + `DebugRunner`（风险最低，纯搬代码，先把 Godot 的「调试代码不进主场景」立起来）
2. `HumanView`（只搬 `_draw`，一眼能对比截图）
3. `HumanNeeds` / `HumanBrain` / `HumanMover`（有行为风险，一次一块，跑 5400 刻验收）
4. 建筑坐标辅助函数（见《建筑坐标与新增建筑.md》A 档）
5. 其余（TickManager 拆分、BuildingView）看心情

每一轮做完都是一次 commit，别攒着。
