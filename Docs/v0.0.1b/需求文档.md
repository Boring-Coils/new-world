# v0.0.1b 需求文档（拆除 / 旋转 / 图标等级 / 状态栏 / 居民详情 / 存档）

> 上一轮 `Docs/v0.0.1a/需求文档.md` 的七条全部完成，本文档是 `v0.0.1` 剩下的部分。
> 本文只写「要什么、什么算做完」，不写实现。

## 依据（用户原话）

- 「拆除和旋转建筑我是想做的，玩家视角的状态栏和居民的详细菜单也要做。存档也要做。这些是我打算0.0.1做好的」
- 「详情页。够。」（拆除的入口走详情页；旋转只做 0° 和 90°）
- 「注意旋转之后图标要保存水平。另外，支持动态调整图标。」
- 「未来建筑可能支持升级操作，不同的等级我希望使用不同的图标」
- 「不改」（升级不改变占地）

## 一、拆除建筑

### 交互

| 项 | 规定 |
|---|---|
| 入口 | 建筑详情页底部的「拆除」按钮 |
| 防误触 | 点一次变「确认拆除？」，再点一次才真的拆；中途点别处或关面板则取消 |
| 反馈 | 拆除后详情页自动关闭，右上角提示「XXX 已拆除」 |

### 规则

1. 建筑里如果站着人，先把人赶出来（和「建筑压在居民身上」时一样的处理），再拆。
2. 建筑占的格子要立刻释放，寻路马上能走。
3. 从建筑名单里移除；如果详情页正看着这栋，面板关闭。
4. 有人正把这栋建筑当目标（正在走过去、或正打算去），这些人要重新做一次决策，不能留在原地发呆。

### 边界

- 预览用的半透明虚影不能走拆除流程。
- 拆到一栋不剩：居民不能报错，应该自己在原地重新决策（此时没有目标就闲置）。
- 拆除不返还资源（0.0.1 没有资源成本概念，先不引入）。

## 二、旋转建筑

### 交互

| 项 | 规定 |
|---|---|
| 支持角度 | 只有 0° 和 90° 两档 |
| 操作 | 放置模式下按 R 键，在当前鼠标格子上切换横竖 |
| 预览 | 切完立刻重算「这一格能不能放」，描边颜色跟着变 |
| 已放置的建筑 | 不能原地旋转。想改朝向就拆了重放 |

### 规则

1. 旋转 = 宽高互换，占格随之互换（4×3 变 3×4）。
2. 入口格子跟着旋转，不能出现「人从原来那一边走进墙里」。
3. 建筑外观要按新宽高重新排版（顶部装饰条、图标、出入口标记的位置都变）。
4. **图标必须保持水平**，不跟着建筑歪。
5. 存档要存旋转状态。

## 三、图标与建筑等级

### 目标

「不同的等级使用不同的图标」——等级现在不做升级操作，但图标接口要能按等级取图，以后加升级不用返工。

### 规则

| 项 | 规定 |
|---|---|
| 等级字段 | 每栋建筑有等级，默认 1 |
| 图标来源 | 按「建筑类型 + 等级」查表取贴图 |
| 图标的朝向 | 永远水平，不随建筑旋转 |
| 图标的大小位置 | 跟着建筑尺寸重算（居中偏下），和现在一致 |
| 升级的作用范围 | **只改数值和图标**，不改占地、不改入口 |
| 0.0.1 是否做升级操作 | 不做。只留字段和图标表 |

### 边界

- 某个等级没有配图时，退回用 1 级的图标，不要出现空白方块。
- 图标是「由等级推导出来的」，**存档不存图标**，读档按等级重算。

## 四、玩家视角状态栏

### 定位

状态栏只提供**显示位置和刷新逻辑**，它不认识任何具体资源。
要显示什么由别的脚本注册进来——以后加水、食物、木材、石料、人口、电量，都只是「多注册一条」，不改状态栏本身。

```
┌────────────────────────────────────────────────┐
│ 💧 水 320/700 │ 🍖 食物 610/700 │ 👥 人口 8 人  │ ← 注册来的条目，从左往右排
│ 第 3 天 08:00                        暂停 ×1   │ ← 固定信息
└────────────────────────────────────────────────┘
```

### 一个条目包含什么

| 字段 | 说明 |
|---|---|
| 图标 | 条目左侧的小图，没有就只显示文字 |
| 名称 | 「水」「食物」「人口」 |
| 当前值 | 每刻变化 |
| 最大值 | 用来显示成「320/700」这样的比例 |
| 排序 | 决定左右顺序，不填就按注册先后 |
| 显示格式（可选） | 默认「当前/最大」；人口这种写「8 人」，时间写「第 3 天 08:00」 |
| 警示阈值（可选） | 低于百分比时数字变红（默认不启用） |

### 图标

状态栏图标**单独准备**，不复用建筑图标（两边尺寸和风格都不同，共用反而别扭）。

| 项 | 规定 |
|---|---|
| 存放位置 | `Assets/UI/StatusBar/`，和建筑图标 `Assets/Icons/` 分开 |
| 命名 | `<条目名>.png`，如 `water.png`、`food.png`、`population.png` |
| 尺寸 | 统一 64×64，透明背景 |
| 显示 | 按行高缩放，保持等比，不拉伸 |
| 缺图 | 只显示文字，不留空白方块 |

### 规则

1. **注册 / 注销都要有**：注册时交出上面那些字段，状态栏返回一个句柄；以后要撤掉某一条，用句柄注销，不用去猜它排第几。
2. **谁提供谁算值**：状态栏每刻问一遍各条目「现在多少」，自己不去遍历居民或建筑。这样以后新增资源不用碰状态栏，也不会出现「所有人扫一遍」的开销。
3. 刷新时机：每刻一次，和 tick 同步；不每帧刷。
4. 画面上的数字必须和实际状态一致——不允许「画面上看着在取水的人数和统计对不上」。
5. 只在屏幕角落占一小块，不遮挡建筑；点建筑、点人时状态栏不跟着动。
6. 条目多到一行排不下时自动换行；换行后状态栏整体变高，不能盖住建筑交互区。
7. 这套接口是给「资源系统」留的口子：0.0.1 只注册人口和平均口渴/饥饿，以后加资源只加条目。

## 五、居民详情菜单

### 交互

| 项 | 规定 |
|---|---|
| 入口 | 左键点居民（点建筑是建筑详情，点人就是居民详情） |
| 位置 | 和建筑详情同一个面板位置（右侧，屏幕宽度的 1/5） |
| 关闭 | 和建筑详情一样：点空白处 / ESC |

### 内容

| 板块 | 行 |
|---|---|
| 基本信息 | 姓名、年龄、年龄段（儿童 / 成年 / 老年） |
| 个人状态 | 口渴、饥饿（数值 + 百分比） |
| 当前行为 | 正在做什么（取水 / 取食 / 工作 / 移动中 / 闲置）、目标建筑名 |
| 身体状态 | 身上的 buff 及剩余时长（没有就隐藏这个板块） |

### 规则

1. 和建筑详情**共用同一套「板块 + 行」的内容协议**，面板本身不认识「建筑」或「居民」。
2. 居民在移动，面板内容要跟着刷新（每刻一次即可，不必每帧）。
3. 居民被拆除建筑赶出来、或目标消失时，面板内容要跟着变，不能卡在旧数据。
4. 点人的判定：人一直在动，点击范围要跟着位置走；**和建筑重叠时建筑优先**——点在建筑上的位置一律开建筑详情。

## 六、存档

### 存什么

| 类别 | 内容 |
|---|---|
| 存档头 | 存档版本号、保存时间 |
| 世界 | 累计刻数、随机种子 |
| 每栋建筑 | 唯一 id、类型、左上角格子、旋转、等级、里面站着的人、建筑自己的状态数据 |
| 每个居民 | 唯一 id、姓名、年龄、年龄段、口渴、饥饿、当前目标（存建筑的 id）、当前行为、所在格子、身上的 buff 及剩余时长、各人的随机偏移 |
| 相机 | 位置、缩放 |

### 规则

1. **引用一律存 id，不存对象**。人的目标建筑要存建筑 id，读档时重新接回去。
2. 读档顺序：先建建筑 → 再建居民 → 最后把人和建筑的关系接上。
3. **随机种子必须存**，否则读档后所有人的行为会和存档前不一样，看起来像坏了。
4. **不存寻路路径**：读档后按当前位置和目标重新算一次路。
5. 存档格式要求：人能看懂、出问题能手动改、不同版本能认出来（版本号对不上就拒绝读取并提示）。
6. 共 **8 个存档槽位**，玩家随时可以存（不限制在哪个界面）。

### 验收

- 存档 → 退出 → 读档，人口数、建筑数、每个人所在格子、口渴饥饿数值、建筑等级和旋转角度全部对得上。
- 读档后继续跑 1 天，不会出现「所有人原地不动」「目标建筑是空的」这类问题。

## 七、这次明确不做

- 升级操作本身（只留字段和图标表）
- 升级改变占地 / 改变入口
- 昼夜与作息
- 资源成本、拆除返还
- 多存档管理界面（先做最简的存/读）
