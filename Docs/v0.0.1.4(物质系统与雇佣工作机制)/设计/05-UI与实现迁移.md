# UI 与实现迁移

## 1. 建筑详情页

### 1.1 雇佣设置

可雇佣建筑详情页需要提供目标人数设置：

- 数值范围 `0..max_workers`
- 显示当前雇员数量
- 显示目标人数
- 隐藏运行阈值不显示
- 不可雇佣建筑不显示该控件

当前 `BuildingDetailPanel` 只支持标签和文本值，并每刻整体重建，不能直接支持可编辑输入。

需要改成通用可交互行：

- 建筑提供控件类型、范围、当前值和写入回调。
- 面板不识别具体建筑。
- 面板每刻刷新数据时，不能销毁正在编辑的控件或抢走焦点。
- 输入值由建筑再次夹取和验证。

### 1.2 工作与仓库信息

建筑详情页可以显示：

- 是否处于工作时间。
- 当前目标人数和雇员人数。
- 正在执行的周期数量或最近工作结果，如果建筑自身需要展示。
- 自带库存容量、已用、预留和可用体积。
- 各物品数量。

建筑不需要显示居民位置或工人路线。

### 1.3 仓库详情页

仓库详情页至少显示：

- 总容量。
- 已用体积。
- 已预留体积。
- 可用体积。
- 废料、金属、塑料、线的数量和体积。

仓库不显示雇佣设置。

## 2. 建筑放置与调试 UI

新增仓库需要同步以下入口：

- `GlobalEnum.BuildingType`
- 建筑图标或占位图标
- `PlacementController.Kind`
- 建筑创建分支
- `DebugUI` 放置按钮
- 放置预览和点击层规则
- 无头自动放置测试

仓库尺寸为 `3×4`，入口规则沿用 `Building.can_place_at()`。

## 3. 现有代码改造面

### 3.1 `Building`

- 增加可选雇佣能力。
- 增加可选自带库存。
- 提供班次和工作类型查询。
- 建筑删除退出时清理雇佣和库存生命周期。

不在 `Building` 基类中强制所有建筑拥有雇佣和库存。

### 3.2 `WorkStation`

- 保留 `occupants` 表示物理站内人数。
- 不再用 `occupants` 表示雇佣人数或正在工作人数。
- 增加雇佣配置、班次和可选自带库存。
- 当前没有产出的测试工作类型必须与正式工作类型区分。

### 3.3 `Human`

- 增加雇主引用。
- 提供受控的雇佣绑定和解除入口。
- 保持 `in_building` 只表示物理位置。
- 居民退出时通知雇主并配合取消周期。

### 3.4 `HumanAI`

- 删除随机寻找工作站的逻辑。
- 从雇主获取工作目标。
- 增加准备阶段和锁定周期阶段。
- 锁定周期内关闭普通生存中断。
- 硬中断时协调周期取消和状态退出。
- 工作目标有效期不再硬编码 `WorkStation`。

### 3.5 `HumanMotion`

- 继续作为唯一移动实现。
- 增加工作需求取用所需的通用格子或建筑移动能力。
- 为等待点半格偏移增加“格子目的地 + 最终局部偏移”能力。
- 将离站逻辑从 `WorkStation` 硬编码改为通用可离站能力。

### 3.6 `World`

- 把 `WAIT_PLACE` 作为正式等待锚点使用。
- 为每个居民生成稳定的等待偏移。
- 等待移动仍经过 `HumanMotion`。
- 世界根节点不承担就业、库存或生产规则。

### 3.7 `TickManager`

- 保持建筑先于居民更新。
- 不以建筑先后顺序计算统一效率。
- 不把库存领域规则塞进时钟。

### 3.8 物资系统

建议建立全局可查询的物资服务，负责：

- 物品定义。
- 库存注册和注销。
- 数量锁定。
- 产出空间预留。
- 库存原子结算。
- 所有者消失后的自动清算。

该服务可以是 Autoload，也可以是世界场景中的唯一节点；无论形式如何，场景中必须只有一个权威实例。

## 4. 迁移顺序

### 阶段 1：物资基础

- 物品定义。
- 库存与体积计算。
- 仓库建筑和放置入口。
- 数量锁定与空间预留接口。
- 建筑自带库存。

### 阶段 2：雇佣基础

- 建筑目标人数和雇员名单。
- 居民雇主引用。
- 合格年龄段。
- 一刻内补齐和随机解雇。
- 详情页人数设置。

### 阶段 3：班次与等待

- 默认班次。
- 下班和未就业等待点。
- 稳定半格偏移。
- 删除随机工作站工作目标。

### 阶段 4：工作周期

- 工作类型契约。
- 准备阶段、锁定阶段和结算阶段。
- 水和食物预测。
- 强制中断和回滚。
- 工作结果提交。
- 周期因眩晕等临时原因中断后从零重新开始。
- 额外产出继续寻找未预留空间，无法存放时进入待结算。

### 阶段 5：生命周期与验证

- 建筑删除。
- 居民死亡和退出。
- 自动清算、拆分和销毁。
- 库存与雇佣无头测试。
- UI 人工检查。

## 5. 兼容现有测试

现有 `TestScene` 会让儿童、成年人和老年人一起寻找工作站，`BuffSelfTest` 也会读取
工作目标。改造后需要同步调整：

- 只有成年人能够被默认雇佣。
- 儿童和老年人失去随机工作站目标。
- 工作周期内眩晕和虚弱的行为与旧测试预期不同。
- 未就业和下班居民会前往等待点。
- 测试统计需要区分“就业”“去雇主”“准备周期”“锁定周期”“下班”。
- 测试场景提供仅调试可用的库存注入、查询和清空入口，用于构造仓库用例。

## 6. 禁止的实现捷径

- 不在建筑里维护居民位置或活动工人集合。
- 不在 `HumanAI` 中直接增删库存。
- 不让建筑详情页为每种建筑写类型分支。
- 不让工作行为直接调用 `AStarGrid2D` 或写位置。
- 不把仓库容量预留实现成普通物品锁定。
- 不把 `in_building` 当作工作状态。
