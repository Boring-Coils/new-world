# 雇佣机制

## 1. 基本关系

雇佣关系由建筑和居民共同表达：

- 建筑记录目标人数、最大人数和当前雇员名单。
- 居民记录自己的雇主。
- 同一居民最多只有一个雇主。
- 没有岗位、职业、技能或工种字段。

是否可雇佣由建筑能力决定。不能雇佣的建筑隐藏或省略雇佣设置，不参与招聘。

## 2. 人数配置

### 2.1 目标人数

玩家可以在可雇佣建筑详情页设置目标人数：

- 最小值：`0`
- 最大值：建筑定义的 `max_workers`
- 初始值：由建筑配置决定

建筑必须把输入值夹到合法范围。目标人数允许低于隐藏运行阈值。

### 2.2 隐藏运行阈值

建筑可以自行定义运行阈值，默认没有。该值：

- 不出现在详情页。
- 不是目标人数的下限。
- 只用于建筑判断自身功能是否完整。
- 不同建筑可以完全忽略。

### 2.3 当前人数

当前雇员数量来自有效雇员名单。已经死亡、离开场景树或失去永久雇佣资格的居民
不得继续计入人数。

## 3. 招聘资格

默认资格：

- 居民有效且位于场景树中。
- 居民当前没有其他雇主。
- 年龄段为成年人。

建筑可以自定义是否允许儿童或老年人。招聘阶段不检查居民能否寻路到工作建筑。

当前代码同时保存 `age` 和 `age_status`，且没有自动增长逻辑。以后加入年龄增长时，
应保证二者有一致的权威来源；建筑在每刻复检时读取更新后的年龄段。

必须区分两类状态：

| 状态 | 例子 | 默认处理 |
| --- | --- | --- |
| 永久失去雇佣资格 | 年龄变化后不再属于允许年龄段 | 解除雇佣并补招 |
| 临时不能工作 | 眩晕、虚弱、当前不在班次 | 保留雇佣，不因此补招 |

建筑可以配置眩晕或虚弱时解雇，但默认不解除。

## 4. 人数调整

建筑在每刻更新中比较有效雇员数量和目标人数。

### 4.1 人数不足

- 在每个游戏刻尝试招聘。
- 在同一个游戏刻尽可能补齐所有空缺，而不是每刻只招一人。
- 如果没有足够合格居民，则保持不足状态，下一刻继续尝试。
- 招聘不检查路径可达性。
- 候选居民多于空缺时，按建筑定义的选择规则招聘。
- 建筑没有自定义选择规则时，使用居民注册顺序，保证结果稳定可复现。

招聘不检查可达性意味着可能出现“雇员已满，但工人无法到达雇主”的情况。
此时居民仍然保留雇佣关系，返回等待点，并在下一次普通工作决策时重新尝试。
建筑不会因为暂时不可达而解雇或补招。

### 4.2 人数超额

- 从有效雇员中随机选择恰好超额数量的人解雇。
- 如果存在已经失去资格的雇员，应先处理资格失效，再对剩余超额人数随机解雇。
- 解雇必须同步通知居民并清理所有相关工作状态。

### 4.3 目标变化

目标人数变化后，在下一个建筑更新刻按相同规则补齐或随机解雇。
UI 修改可以立即夹取合法值，但实际人数调整允许在下一刻完成。

## 5. 资格复检

建筑每刻检查自己的雇员是否仍然有效：

- 居民节点是否有效。
- 居民是否仍在场景树中。
- 居民是否仍指向本建筑。
- 是否满足建筑的年龄段和其他永久资格。

资格失效时：

1. 从雇员名单移除。
2. 清空居民雇主引用。
3. 通知居民雇佣已结束。
4. 取消该居民与当前建筑有关的工作周期。
5. 在同一刻尝试补招。

资格失效通知可以同步发出，但 AI 的状态退出和视觉恢复仍由居民侧在安全路径中完成。

## 6. 班次

### 6.1 默认班次

默认工作时间为当前游戏日的半开区间：

```text
[n / 3, 5n / 6)
n = TickManager.TICKS_PER_DAY
```

当前 `n = 1800`，所以默认是第 `600..1499` 刻。

### 6.2 班次规则

- 班次外不能开始新的工作周期。
- 周期开始前必须先满足班次条件。
- 周期开始后，即使跨过下班时刻，也必须完成当前周期。
- 周期结束后如果已经下班，不再开始下一轮。
- 建筑可以提供不同班次，包括未来的跨午夜班次。

### 6.3 默认工作类型配置

每栋可雇佣建筑至少需要提供：

- 是否可雇佣。
- 最大人数。
- 初始目标人数。
- 默认允许年龄段。
- 可选运行阈值。
- 默认班次。
- 工作类型。
- 可选自带库存容量，默认工作建筑为 `1000`。

## 7. 雇佣通知

居民需要知道以下事件：

- 被雇佣。
- 被目标人数调整解雇。
- 因永久资格失效被移除。
- 雇主建筑被删除。

通知至少需要让居民：

- 更新或清空雇主引用。
- 退出锁定工作周期。
- 释放尚未结算的需求和产出预留。
- 停止前往或停留在旧雇主工作地点的普通工作行为。
- 重新进入空闲、补给或等待流程。

## 8. 下班与等待

未就业和下班居民不应随机前往工作站。生存需求满足后，他们前往
`World.WAIT_PLACE` 附近等待：

- 等待位置以 `WAIT_PLACE` 为锚点。
- 每个居民使用稳定随机偏移，范围不超过半格。
- 不应每刻重新随机造成抖动。
- 偏移后仍应保证位置可走。
- 等待是低优先级行为，可以被水和食物需求打断。
- 当前版本使用世界等待点；有住宅后优先回家。

## 9. 生命周期

### 9.1 建筑删除

建筑退出场景树时：

- 从 `TickManager` 注销。
- 通知所有雇员雇佣结束。
- 取消与该建筑有关的周期。
- 释放建筑相关的物品锁定和产出预留。
- 清空雇员名单。
- 按物资系统规则处理自带库存。

### 9.2 居民死亡或退出

居民退出场景树时：

- 从 `TickManager` 注销。
- 从雇主雇员名单移除。
- 取消当前工作周期。
- 释放其持有的物品锁定和产出预留。
- 将尚未消耗的工作需求自动退回来源仓库。
- 取消尚未入库的临时产出。
- 不按居民位置寻找仓库。只有来源仓库也消失时，才按来源建筑左上角执行自动清算。

## 10. 不变量

- 一个居民最多属于一个雇主。
- 建筑雇员名单不包含无效居民。
- 失去永久资格的居民不会继续计入目标人数。
- 临时眩晕或虚弱不会在没有配置时导致解雇。
- 招聘不依赖居民当前位置或可达性。
- 建筑不维护居民路径或当前工作位置。
