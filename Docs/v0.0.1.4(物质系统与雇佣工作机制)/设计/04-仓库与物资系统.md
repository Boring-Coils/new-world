# 仓库与物资系统

## 1. 物品定义

本版只有四种物品：

| 物品 | 单位体积 |
| --- | ---: |
| 废料 | 2 |
| 金属 | 1 |
| 塑料 | 1 |
| 线 | 1 |

物品数量使用整数。总占用体积为：

```text
已用体积 = Σ(物品数量 × 单位体积)
```

不记录物品形状、占格、旋转或堆叠方式。

物品定义应集中管理，避免在库存、UI 和工作行为里重复写体积常量。

## 2. 库存模型

每个库存至少包含：

- 总容量。
- 各物品的可用数量。
- 已用体积。
- 已预留产物体积。

当前可用体积：

```text
可用体积 = 总容量 - 已用体积 - 已预留产物体积
```

必须满足：

```text
已用体积 + 已预留产物体积 <= 总容量
```

物品锁定不会减少已用体积。被锁定物品仍在库存中，只是对应数量不能被其他对象使用。

详情页建议分别显示：

- 已用体积。
- 已预留体积。
- 当前可用体积。
- 各物品的可用数量和被锁定数量。

## 3. 仓库建筑

仓库是不需要雇佣居民的独立建筑：

- 尺寸：`3×4`
- 默认容量：`2000`
- 入口规则与普通建筑一致
- 不提供招聘设置
- 可接收任意合法物品存入
- 允许居民从中取用物品

仓库的存在不要求居民在产出结算时实际走过去。

## 4. 建筑自带库存

大多数可工作建筑可以拥有自带库存：

- 默认容量：`1000`
- 是否拥有由建筑配置决定
- 使用与仓库相同的库存和预留规则
- 随建筑创建和删除

非工作建筑是否拥有自带库存也由建筑自己决定。

## 5. 权限

### 5.1 建筑自带库存

存入：

- 非雇员不能存入任意物品。
- 库存只接收本建筑自己的工作产出。
- 普通居民不能把它当作公共仓库倾倒物资。

取出：

- 任何居民都可以取出可用物品。
- 已经被锁定的数量不能取出。

建筑所有者消失后的自动清算不属于普通居民存入，不按普通权限判断。

### 5.2 外部仓库

外部仓库用于公共存储：

- 建筑产出可以存入。
- 所有者消失后的自动清洗可以存入。
- 居民可以取用未锁定物品。

外部仓库不要求居民属于某个建筑。

## 6. 物品锁定

物品锁定发生在居民明确决定取用某个数量时：

- 锁定对象是物品类型和具体数量。
- 锁定期间其他对象不能使用该数量。
- 锁定必须绑定到居民、工作周期或等价的事务标识。
- 取走后库存数量减少，物品进入居民携带状态。
- 周期成功时，携带物品转为实际消耗。
- 周期取消时，携带物品自动归还，不要求居民走回仓库。
- 来源库存消失时，锁定失效，居民重新寻找目标。

锁定不预留空位，也不属于产出空间预留。

该锁定规则适用于所有库存和所有未来的物品使用场景，不局限于工作周期需求。

## 7. 产出空间预留

产出空间在周期开始前预留：

- 数量依据工作类型定义的本轮正常产出计算。
- 预留的是体积，不是具体物品。
- 预留必须绑定到工作周期。
- 周期成功时转为实际库存。
- 周期取消时释放。
- 产出少于预留量时，释放多余部分。

空间预留与物品锁定是两种不同事务：

| 事务 | 对象 | 目的 |
| --- | --- | --- |
| 物品锁定 | 已存在的物品数量 | 防止需求被抢走 |
| 空间预留 | 尚未存在的产出体积 | 保证周期能够结算 |

## 8. 工作需求取用

居民取用工作需求时：

1. 优先检查雇主自带库存。
2. 雇主库存不足时，按实际可达路径寻找最近外部仓库。
3. 一个仓库不足时，允许继续从其他最近仓库拆分取得。
4. 每次决定取用时立即锁定。
5. 取得完整需求后，才允许开始周期。

招聘阶段不检查可达性。只有实际取用工作需求时，才通过 `HumanMotion` 检查路径和入口。

## 9. 产出存入

周期成功时，产出按照以下顺序存入：

1. 雇主自带库存中已经预留的空间。
2. 外部仓库中已经预留的空间。
3. 拆分到多个已经完成预留的仓库。

产出不需要居民前往仓库，结算由物资系统直接完成。

如果实际产出超过预留体积：

1. 已预留空间仍然优先使用。
2. 剩余产出继续寻找其他未预留的可用仓库空间。
3. 额外产出可以拆分到多个仓库。
4. 额外产出不能占用其他周期的预留空间。
5. 当前没有可用空间时，本轮保持待结算，下一 tick 继续寻找。

待结算期间，居民不能开始下一轮工作。待结算产出在成功存入前不计入建筑库存；
如果居民在存入前死亡或建筑被删除，这部分产出按周期取消处理。

如果预留仓库已经消失：

- 先重新预留等量空间。
- 成功时继续结算。
- 失败时取消周期并回滚需求锁定。

## 10. 距离与排序

### 10.1 自动转移

建筑库存自动转移时，以来源建筑左上角为距离起点。

本设计建议使用八方向格距，即 Chebyshev 距离，因为该转移不需要实际寻路。
距离相同时必须使用稳定排序，例如坐标字典序，避免同一场景出现不确定结果。

### 10.2 居民实际取用

居民需要实际前往外部仓库时，应按居民到仓库入口的实际可达路径距离选择，而不是只看直线距离。

## 11. 所有者消失后的自动清算

适用于建筑或仓库所有者消失：

- 建筑被删除。
- 建筑自带库存随建筑消失。
- 仓库被删除。

处理顺序：

1. 取消相关雇佣和工作周期。
2. 释放该所有者相关的物品锁定和空间预留。
3. 收集建筑库存、居民携带物和临时产出。
4. 以建筑左上角为距离起点寻找可用仓库。
5. 优先放入最近且有足够空间的一个仓库。
6. 放不下时，按距离顺序拆分到多个仓库。
7. 所有仓库仍无法容纳的剩余数量销毁。
8. 清空库存、锁定和所有者引用。

自动清算只能使用未被其他周期预留的空间。它不能抢占其他工作的产出预留。

### 11.1 居民死亡或离开场景树

居民不是库存所有者，因此居民死亡或离场不触发本节的距离排序。

- 未消耗的工作需求自动退回来源仓库。
- 尚未入库的临时产出直接取消。
- 工作周期使用的物品锁定和产出预留全部释放。
- 如果来源仓库也已经消失，才以来源建筑左上角为起点执行自动清算。
- 不使用居民死亡位置寻找仓库。

## 12. 原子性

以下操作必须原子完成：

- 物品数量锁定。
- 物品数量释放。
- 需求转为消耗。
- 产出空间预留。
- 预留空间转为实际库存。
- 一次自动清算中的多仓库拆分。

任何操作失败都不能留下半扣库存、半写产出或孤立预留。

## 13. 生命周期

- 仓库删除时，先使相关预留失效，再清算库存。
- 建筑自带库存随建筑删除。
- 库存所有者删除时执行自动清算。
- 场景整体退出或游戏关闭不属于游戏内删除，不应触发物资迁移和销毁日志。
