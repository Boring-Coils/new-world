# v0.0.1.6 统计与显示最终需求

本文档整理当前讨论后确认的 v0.0.1.6 需求，作为后续实现与验收依据。
原始口语描述继续保留在
[`让我先用超级口语的方式描述这次更新需要做什么吧.md`](./让我先用超级口语的方式描述这次更新需要做什么吧.md)，
与本文冲突时以本文为准。

## 1. 目标与范围

v0.0.1.6 新增一条面向玩家的常驻状态栏，并补齐它依赖的物资汇总、人口统计、
时间显示和悬停详情能力。

状态栏属于正式玩家 UI，不属于 `DebugUI`。本版本不增加点击操作，但状态栏必须
接收鼠标事件，不能设置成鼠标穿透。

## 2. 状态栏外观与交互

- 状态栏是一条横向常驻 UI，放在屏幕顶部中央，顶边紧贴屏幕上边缘。
- 外形暂定为倒置梯形，具体上下边比例、颜色和装饰后续通过视觉效果调整。
- 当前底板透明度约为 `0.5`，图标、文字和分隔线同步降低透明度。
- 状态栏宽度随已注册信息项动态变化，不固定为唯一宽度。
- 如果没有需要显示的内容，可以缩得很小。
- 状态栏整体不能穿透。鼠标位于状态栏范围内时，事件不能继续传给状态栏下方的
  世界、建筑和其他界面。
- 当前没有需要点击的信息，但每个信息项都必须具备悬停能力。
- 鼠标移入信息项时，由该信息项自行决定是否显示详情以及显示什么内容。

## 3. 第一行：物资储量

### 3.1 显示项目

当前按以下顺序显示六种物资：

1. 水
2. 食物
3. 废料
4. 塑料
5. 金属
6. 线

每种物资采用“白色图标 + 右侧数量”的格式。不同物资之间使用灰白色细竖线分隔。

正式实现时应有统一的白色素描或剪影图标。当前项目已有取水站和取食站图标（颜色不正确），
但废料、塑料、金属、线等物资图标尚未齐备，需要在实现阶段补充。

### 3.2 注册与更新

- 物资显示项由物资管理脚本在进入场景时注册一次。
- 注册内容表示“要显示哪个物资及其图标和详情来源”，不能每个游戏刻重复注册。
- 物资数量变化时，由计数或物资管理逻辑通知状态栏，不通过状态栏逐刻轮询。
- 状态栏按注册顺序创建物资项，并缓存当前显示结果。
- 收到变更后重新计算汇总值；显示值没有变化时不必重绘。

### 3.3 物资统计口径

普通物资只统计当前场景中所有有效仓库的库存，包括：

- 任意有储存能力的建筑中的物资。
- 已被工作周期或居民锁定、但尚未从仓库取走的物资。

以下内容不进入普通仓库储量：

- 居民随身背包中的物资。
- 放置预览或其他不在可用状态的建筑。

例如，居民从仓库取出物资并放进背包后，该物资将从状态栏储量中消失。

### 3.4 物资悬停详情

- 物资悬停详情只显示该物资的总数和已锁定数量。
- 存在无限来源时，“总数”显示“无限”；“已锁定”仍显示仓库中的实际锁定量。

### 3.5 无限物资

如果场景中存在对应物资的无限材料站，其储量按 `-1` 表示无限：

- 状态栏显示中文“无限”，不显示 `-1`。
- 即使仓库中同时存在同类有限物资，也显示“无限”。
- 无限状态由有效且仍在场景内的无限材料站决定；站被移除后，恢复按仓库汇总。
- 当前无限来源为无限取水站和无限取食站。

## 4. 第二行：状态信息

第二行当前包含两块信息：

1. 儿童、成人、老人数量。
2. 当前游戏时间。

### 4.1 人口数量

- 以居民的 `age_status` 为准，分别统计儿童、成人和老人。
- 只统计当前场景中仍然有效、未离场的居民。
- 居民登记、离场或其年龄阶段变化后，人口显示需要随之更新。
- 人口摘要显示各年龄段的居民总数。
- 悬停详情改为显示儿童、成人、老人各自没有有效雇主的人数。

### 4.2 时间格式

时间固定显示为：

```text
dddd天tttt刻
```

- 天数从第 1 天开始显示，并使用四位补零。
- 当天刻数从 `0` 到 `1799`，使用四位补零。
- 例如游戏第一天开始时显示 `0001天0000刻`。
- 代码中的游戏日序号仍可从 0 开始保存，UI 显示时加 1。
- 时间只显示摘要，不提供悬停详情。

## 5. 时间与速度常量

以下数值正式固定，不再随意调整：

- 一个游戏日：`1800` 刻。
- 默认现实走时速度：每现实秒 `6` 刻。
- 因此默认情况下，一个游戏日约等于现实 `300` 秒。

现实走时速度只影响游戏推进的快慢，不改变游戏内一天包含的刻数。

## 6. 悬停详情的动态机制

每个状态栏信息项除了摘要值，还可以提供详细信息。详细信息不能假定为静态文本。

### 6.1 信息项契约

每个信息项注册或持有的内容至少包括：

- 稳定标识。
- 图标或标题等固定外观数据。
- 摘要值来源。
- 详情提供者。

详情提供者由信息项自身决定：

- 返回空内容时，不显示详情。
- 返回非空内容时，状态栏负责统一弹出和关闭详情面板。
- 详情内容可以使用通用的板块、标题和文本行结构，避免状态栏写死水、食物、
  人口或时间类型。

### 6.2 获取与刷新时机

- 详情关闭时，不持续生成详细信息。
- 鼠标移入时，立即向对应详情提供者获取一次最新内容。
- 详情展开期间，相关数据发生变化时重新获取并刷新。
- 鼠标移出、详情关闭后，停止该详情的内容刷新。
- 更新采用事件驱动，不使用 `_process` 或无条件每刻轮询所有信息项。
- 刷新前可以比较新内容与当前内容，完全相同则不重复更新界面。

不同信息项的数据源变化频率不同：

- 物资详情在仓库数量、锁定状态或无限材料站发生变化时刷新。
- 人口详情在居民登记、离场或年龄阶段发生变化时刷新。
- 时间详情在时间推进时刷新；如果当前详情包含逐刻变化的时间信息，则可以在
  每次时间变化时更新。

“详情展开期间实时更新”指按相关数据源的变更更新，不等于详情展开后每刻强制
重新查询所有内容。

## 7. 与当前代码的衔接要求

实现时需要处理以下现有差异：

- `TickManager.TICKS_PER_DAY` 当前已经是 `1800`，
  `TICKS_PER_SECOND` 当前已经是 `6.0`，时间常量无需重新设计。
- `TickManager.get_day()` 当前从 0 开始，状态栏显示时加 1。
- 居民已有 `GlobalEnum.AgeStatus`，人口数量使用该字段统计。
- `MaterialTypes.ItemType` 当前只有废料、金属、塑料和线；水、食物需要加入统一的
  物资类型或等价的显示注册体系。
- 无限取水站和无限取食站当前只在建筑详情中显示 `-1`，需要补充可供统计系统查询
  的无限物资接口。
- `MaterialSystem.inventory_changed` 已能报告多种库存变化，但直接调用
  `add_items_unchecked()` 等库存写操作不一定触发该信号。所有会影响仓库汇总的写入
  必须经过统一通知路径，或在初始化完成后主动发布一次完整快照。
- 仓库锁定物资仍保存在 `Inventory.items` 中，按库存数量汇总时天然包含锁定物资，
  不需要再额外加上锁定量。
- 状态栏根控件必须接收鼠标，不能使用 `MOUSE_FILTER_IGNORE`。
- 状态栏遮挡较大时，通过减小高度、缩小间距、动态宽度和视觉尺寸处理，不能通过
  鼠标穿透解决。

## 8. 实现建议边界

- 新建独立的玩家状态栏组件，不把统计显示逻辑写进 `DebugUI`。
- 状态栏可由 `World` 统一挂载，使主场景和集成检查场景显示一致。
- 物资管理侧负责注册显示项并提供汇总快照或变化通知。
- 状态栏负责统一布局、图标、分隔线、摘要显示、悬停详情面板和鼠标拦截。
- 各信息项负责自己的摘要来源、详情内容和是否显示详情。
- 人口统计优先通过居民登记和离场通知更新，不依赖逐帧扫描。
- 详情刷新使用现有库存、居民和时间信号，避免新增独立模拟循环。

## 9. 验收清单

实现完成后至少确认：

- 状态栏是正式玩家 UI，视觉上不与调试面板混用。
- 状态栏整体不穿透鼠标，悬停时不会触发下方建筑或世界操作。
- 六种物资按约定顺序显示白色图标、数量和灰白色细竖线。
- 物资项只在进入场景时注册一次。
- 仓库内物资数量变化会更新第一行。
- 锁定但仍留在仓库中的物资仍被统计。
- 居民背包中的物资和普通建筑自带库存不进入第一行。
- 存在无限取水站或无限取食站时，对应物资显示“无限”。
- 无限材料站移除后，物资恢复按仓库数量显示。
- 儿童、成人、老人数量与实际 `age_status` 一致。
- 时间按要求显示为 `dddd天tttt刻`，第一天从 `0001天0000刻` 开始。
- 每个信息项都能自行决定是否显示悬停详情。
- 物资详情只包含总数和已锁定数量。
- 人口详情显示各年龄段无工作人数。
- 时间项悬停时不显示详情。
- 详情打开时，其动态内容能够随对应数据变化更新。
- 详情关闭后，不继续无条件生成或轮询详情内容。
- 无头运行中不存在 `SCRIPT ERROR`、未预期错误或持续告警。
- 状态栏紧贴屏幕上边缘，底板透明度约为 `0.5`；形状、尺寸、文字、图标清晰度
  和鼠标悬停范围需要通过实际界面人工检查。
